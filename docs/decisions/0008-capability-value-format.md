# ADR-0008: รูปแบบค่าของ `capability` — ตัวคั่นที่มีขอบ และการยืมคำศัพท์กลาง

**Status:** Proposed
**Date:** 2026-10-12
**Depends on:** ADR-0002
**Blocking:** การทำตัวกรองด้วย capability ฝั่งระบบ coordination
**Supersedes:** —
**Related ws-001:** `dis-3b5cb137` seq 68 · seq 77 · seq 80 · seq 81 · `dis-a84b7a8e` seq 5

## Context

✅ 12 ต.ค. 2026 ระบบ coordination เพิ่มช่อง `capability` บนใบส่งงาน พร้อมคำกำกับที่ถูกทั้งหมด
(เป็นคำประกาศของผู้ส่ง · ไม่ตรวจ · ไม่ใช้ตัดสินสิทธิ์) และ **จงใจไม่ทำตัวกรอง** โดยให้เหตุไว้ว่า

```
ตัวกรองแบบตรงตัว   ถาม "b" จะไม่ match "a,b"     → พลาดใบที่ทำได้
ตัวกรองแบบ LIKE    ถาม "b" จะ match "bc" ด้วย    → หยิบใบที่ทำไม่ได้
```

แล้วขอว่า **"ถ้าต้องการตัวกรองจริง ขอรูปแบบของค่าให้ตายตัวก่อน"** — การไม่เดาเป็นการตัดสินใจที่ถูก

🟡 แต่คำขอนั้นเป็นสองคำถามที่ปนกัน และแยกออกแล้วข้อแรกไม่ต้องรอข้อตกลงใด

✅ ส่วนคำถามที่สอง (ค่าอะไรใช้ได้) มีคำศัพท์กลางอยู่แล้ว — `capability/v1` ของ `agent-platform`
มี taxonomy 14 ค่าพร้อมแผนที่ scope · และเขาเตือนแผลนี้ไว้ตั้งแต่ 10 ก.ย. (`dis-a84b7a8e` seq 5)

> `deny filesystem` กับ `deny fs.write` **ไม่คุ้มกันและกัน และไม่มีอะไรฟ้อง**

## Options

### A. แก้ที่ขอบของ token + ยืมคำศัพท์กลาง (แนะนำ)

* ✅ ตัวกรองถูกทั้งสองทางโดยไม่ต้องรู้ว่าค่าที่อนุญาตมีอะไรบ้าง
* ✅ ค่าในฐานยังเป็นค่าว่างทั้งหมด — **ตอนนี้คือตอนที่ถูกที่สุด** ไม่มีของเก่าให้ migrate
* ❌ ต้อง normalize ตอนเขียน ไม่ใช่ตอนอ่าน

### B. ตั้งคำศัพท์ชุดใหม่ของระบบ coordination เอง

* ✅ ควบคุมได้เต็มที่
* ❌ ได้คำศัพท์ capability ชุดที่สองที่ไม่มีใครประกาศความสัมพันธ์กับชุดแรก = แผลที่ seq 5 เตือนไว้

### C. ไม่ทำตัวกรองเลย ให้ผู้เรียกดึงทั้งหมดมากรองเอง

* ✅ ถูกต้องเสมอ และวันนี้ทำได้แล้วเพราะมี pagination
* ❌ ผู้เรียกทุกรายต้องเขียนตัวกรองเอง และจะเขียนผิดกันคนละแบบ

## Decision

**A** — สองส่วน แยกกันเดินได้

### ส่วนที่ 1 · ตัวคั่นที่มีขอบ — ทำได้ทันที ไม่ต้องตกลงคำศัพท์

```
เก็บ/เทียบโดยหุ้มด้วยตัวคั่นทั้งสองด้าน

  ','  ||  capability  ||  ','      LIKE  '%,' || :ask || ',%'

  "a,b"  →  ",a,b,"      ถาม "b"   →  "%,b,%"   match    ✓
                         ถาม "bc"  →  "%,bc,%"  ไม่ match ✓
```

เงื่อนไขรูปแบบที่ต้องประกาศคู่กัน สามข้อ ตรวจได้ตอนเขียน

```
1  ตัวคั่นคือ ',' เท่านั้น
2  ห้ามมีช่องว่างรอบตัวคั่น (normalize ตอนเขียน)
3  token ห้ามมี ',' อยู่ข้างใน      ← ข้อที่ทำให้ข้อ 1–2 มีความหมาย
```

### ส่วนที่ 2 · คำศัพท์ — ยืม ไม่ตั้งใหม่

| กรณี | ทำอย่างไร |
|---|---|
| ความสามารถที่มีในคำศัพท์กลาง | ใช้ค่าตามนั้นตรง ๆ **ไม่สะกดใหม่** |
| ต้องซอยละเอียดกว่าของกลาง | **ประกาศว่าซอยมาจากค่าใด** ไม่ตั้งชื่ออิสระ |
| ไม่มีในคำศัพท์กลางเลย | ใช้ได้ แต่ต้องรายงาน เพราะอาจเป็นสัญญาณว่าของกลางขาด |

**ที่ไม่ทำ:** ไม่ให้ระบบตรวจว่า token อยู่ในคำศัพท์ที่อนุญาต (จะกลายเป็นชุดปิดโดยไม่ได้ตั้งใจ) ·
ไม่ทำ `AND` หลายค่าในคำขอเดียว (เป็นการเลือกผู้รับ ไม่ใช่การกรอง)

**Reason:** ปัญหาตัวกรองถูกครึ่งเดียวเกิดจาก **token ไม่มีขอบ** — แก้ที่ขอบ ไม่ต้องแก้ที่คำศัพท์
ทั้งสองส่วนจึงเดินแยกกันได้ และส่วนที่ 1 ไม่บล็อกใคร

**Authority:** — `Proposed` · ส่วนที่ 1 เป็นของระบบ coordination ตัดสิน ส่วนที่ 2 เป็นของรีโปนี้ร่วมกับ `agent-platform`

## Consequences

* ระบบ coordination ทำตัวกรองที่ถูกทั้งสองทางได้โดยไม่ต้องรอใบนี้ผ่าน
* ค่าที่ซอยละเอียดต้องมีที่ประกาศความสัมพันธ์ — เป็นงานของรีโปนี้ที่ยังไม่ได้ทำ
* การเลือกผู้รับจากความสามารถ **ทำบนช่องนี้ไม่ได้** เพราะช่องนี้บอกว่า *งานต้องใช้อะไร*
  ไม่ใช่ *ใครทำได้* — คนละด้านของสมการ ต้องมีทะเบียนความสามารถของผู้รับที่ตรวจสอบได้ก่อน
