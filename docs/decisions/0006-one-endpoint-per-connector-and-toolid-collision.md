# ADR-0006: หนึ่ง endpoint ต่อหนึ่งต้นทาง · ชื่อ tool ชนกันให้ปฏิเสธ ไม่ใช่เลือกตัวใดตัวหนึ่ง

**Status:** Proposed
**Date:** 2026-10-12
**Depends on:** —
**Blocking:** ADR-0007
**Supersedes:** —
**Related ws-001:** `dis-514ae7a7` seq 7 ข้อ ข-5 · seq 14 · `dis-a84b7a8e` seq 5 · `dec-f7cbd10c` เกณฑ์ 5

## Context

ระบบที่รวม tool จากหลายต้นทางมาไว้ที่ปลายทางเดียว **จะเจอชื่อซ้ำ** และ `agent-platform` ตีพิมพ์กฎการแปลงชื่อไว้แล้ว
(ADR-0027 ของเขา) โดยข้อที่สำคัญที่สุดคือ **แปลงแล้วชนกันให้ปฏิเสธ ไม่ใช่เลือกอันใดอันหนึ่ง**

เหตุผล: การชนเกิดจากการแปลงของเราเอง ไม่ใช่ความผิดของต้นทาง · และการปล่อยเงียบแปลว่า
**tool คนละตัวอยู่หลัง id เดียวกัน** แล้วนโยบายที่เขียนถึงตัวหนึ่งจะไปคุมอีกตัวโดยไม่มีใครรู้

✅ เขา probe ของจริงมาแล้วกับ server สองตัวและ connector บุคคลที่สามสองราย — ชื่อ tool จริงมีทั้ง kebab-case
และ SCREAMING_SNAKE **การเติม namespace เฉย ๆ ไม่พอ ต้อง sanitize ด้วย**

🟡 ร่างแรกของ runtime ไม่ระบุว่าไคลเอนต์เลือกต้นทางอย่างไร — เราชี้ที่ `dis-514ae7a7` seq 7 ว่า
คำตอบนั้นกำหนดว่าชื่อจะชนหรือไม่ และทีม runtime เลือกทางที่ตัดปัญหาออกตั้งแต่ต้น

## Options

### A. หนึ่ง endpoint ต่อหนึ่งต้นทาง (แนะนำ)

* ✅ ชื่อ tool ไม่มีทางชนกัน — ตัดคลาสของปัญหาออก ไม่ใช่ไล่ปิดรูป
* ✅ นโยบายคีย์ด้วย (ต้นทาง, ชื่อ tool) ได้ตรง ๆ ไม่ต้องแปลงชื่อ
* ❌ ไคลเอนต์ต้องรู้ว่าจะคุยกับต้นทางไหน · เปิดหลาย connection ถ้าต้องใช้หลายต้นทาง

### B. รวมหลายต้นทางไว้ที่ endpoint เดียว + กฎการแปลงชื่อ

* ✅ ไคลเอนต์เห็น tool ทั้งหมดในที่เดียว
* ❌ ต้องมีกฎการแปลง + sanitize + ปฏิเสธเมื่อชน ซึ่งถูกทั้งหมดแต่เป็นของที่ต้องถูกทุกครั้งตลอดไป

## Decision

**A สำหรับรอบแรก** — หนึ่ง endpoint ต่อหนึ่งต้นทาง (เช่น `/connector/<id>/mcp`)

**เมื่อใดที่รวมต้นทางจริง ให้ใช้กฎนี้โดยไม่มีข้อยกเว้น**

```
แปลงชื่อแล้วชนกัน  →  ปฏิเสธทั้งชุด
                     ไม่ใช่เลือกตัวแรก ไม่ใช่เลือกตัวหลัง ไม่ใช่เติมเลขต่อท้าย
```

**Reason:** การตัดคลาสของปัญหาออกถูกกว่าการไล่ปิดรูปที่คิดออก — หลักเดียวกับ ADR-0002
และกับที่ทีม consumer 🔒 สรุปไว้เองเรื่อง cursor ที่พัง ว่าการไล่ตรวจรูปที่คิดถึง
**ปล่อยรูปที่ยังไม่มีใครคิดถึงให้ผ่านอยู่ดี**

**Authority:** — `Proposed` · ทีม runtime 🔒 ใช้ A อยู่แล้วตั้งแต่ 17 ก.ย. และเป็นเกณฑ์ข้อ 5 ของ `dec-f7cbd10c`
ซึ่งเจ้าของงานอนุมัติแล้ว — ใบนี้บันทึกเหตุผลและรูปของ B ไว้สำหรับวันที่จะรวมจริง

## Consequences

* นโยบายคีย์ด้วย (ต้นทาง × ชื่อ tool) ไม่ต้องมีชั้นแปลงชื่อในรอบแรก
* ชุด conformance ต้องมีเวกเตอร์ที่ **จัดให้ชื่อชนกันจริง** แล้วยืนยันว่าปฏิเสธทั้งชุด
  — ไม่ใช่แค่ยืนยันว่าไม่มีชื่อชนในชุดที่ใช้งานอยู่
* การเปลี่ยนไป B ภายหลังเป็นการเพิ่มชั้น ไม่ใช่การแก้ความหมายของคีย์เดิม
