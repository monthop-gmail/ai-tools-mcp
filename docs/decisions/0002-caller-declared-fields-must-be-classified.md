# ADR-0002: ช่องที่ผู้เรียกประกาศเอง ต้องถูกจัดประเภทเป็น enforced หรือ diagnostics

**Status:** Proposed
**Date:** 2026-10-12
**Depends on:** ADR-0001
**Blocking:** —
**Supersedes:** —
**Related ws-001:** `dis-514ae7a7` seq 13–14 · `dis-3b5cb137` seq 80 · seq 84 · `dis-fa078bf8` seq 93 · seq 97

## Context

ช่องที่ "ผู้เรียกประกาศเอง" โตขึ้นเรื่อย ๆ และเกิดคนละเวลา — ชื่อที่ประกาศ · บริบทของงาน · ความสามารถที่ใบต้องใช้ ·
หมายเหตุเรื่องตัวตน · วันนี้มีอย่างน้อยสี่ช่อง

✅ คำกำกับของแต่ละช่องถูกทุกช่อง (*เป็นคำประกาศ · ไม่เคยตรวจ · ไม่ใช้ตัดสินสิทธิ์*)
**แต่กระจัดกระจาย** — ช่องที่ห้าที่ใครเพิ่มพรุ่งนี้ไม่มีอะไรบังคับให้เขียน

✅ แผลเดียวกันเกิดแล้วในของจริง: ที่ `dis-514ae7a7` seq 13 เราชี้ว่า claim ชื่อ `ops` ในโทเคน
**ไม่มีข้อใดในลำดับการตรวจที่สั่งให้ใครตรวจมัน** จึงเป็นฟิลด์ที่มีคนใส่ค่าแต่ไม่มีใครทำอะไรกับค่านั้น

✅ ทีม runtime 🔒 แก้แล้วและตอบกลับด้วยประโยคที่กลายเป็นหลักของเรื่องนี้:
> **"การแก้รอบที่แล้วแก้ที่ตัวอย่าง ไม่ได้แก้ที่ชนิดของปัญหา"**

แล้วทำเป็นตารางในโค้ด (`CLAIM_CONTRACT`) + เทสต์สองชั้น · ✅ ทีม consumer 🔒 หยิบหลักนี้ไปใช้วินิจฉัยบั๊กคนละตัว
(`dis-fa078bf8` seq 97) ภายใน 17 นาทีหลังเราโพสต์ — หลักนี้ใช้ข้ามเรื่องได้จริง

## Options

### A. ตารางเดียวต่อระบบ + เทสต์ที่ทำให้ช่องใหม่ที่ไม่ได้จัดประเภทพัง (แนะนำ)

* ✅ แก้ทั้งตระกูล ไม่ใช่ทีละช่อง · พิสูจน์เป็นโค้ดไปแล้วในรีโป runtime
* ✅ ช่องใหม่ถูกบังคับให้ตัดสินตอนเพิ่ม ไม่ใช่ตอนมีคนถาม
* ❌ ต้องมีที่เดียวที่ถือตาราง และทุกระบบต้องยอมอ้างตารางเดียวกัน

### B. เขียนคำกำกับที่ตัวช่องทุกช่อง ตามที่ทำอยู่

* ✅ ไม่ต้องตกลงอะไรเพิ่ม
* ❌ ขึ้นกับความจำของคนเพิ่มช่อง — ซึ่งเป็นสาเหตุที่ `ops` รอดมาได้

## Decision

**A** — ทุกช่องที่ค่ามาจากผู้เรียก ต้องถูกจัดประเภทอย่างใดอย่างหนึ่ง

```
enforced      มีข้อในลำดับการตรวจ และมีรหัสปฏิเสธของตัวเอง ไม่ฝากรหัสของช่องอื่น
diagnostics   ประกาศชัดว่าใช้ประกอบ/สอบย้อนเท่านั้น · ห้ามมีผลต่อ authn/authz/authorship
```

**ไม่มีช่องที่อยู่เฉย ๆ** · และต้องมีเทสต์สองข้อที่บังคับตาราง ไม่ใช่กฎที่ต้องจำ

```
1  ช่องใหม่ที่ไม่ได้ลงตาราง   →  เทสต์แดงทันที
2  ทุกช่องใน enforced       →  ต้องมีรหัสปฏิเสธของตัวเอง
```

**Reason:** คำกำกับที่ถูกแต่กระจัดกระจาย กันช่องที่ห้าไม่ได้ · เทสต์ที่อ่านตารางเองกันได้
และข้อ 2 คือข้อที่ทำให้ `enforced` ไม่กลายเป็นป้ายที่แปะไว้เฉย ๆ

**Authority:** — `Proposed` · ขอให้ผู้ถือแต่ละระบบรับไปใช้กับช่องของตัวเอง ไม่ใช่ให้ที่นี่สั่ง

## Consequences

* ระบบที่มีโทเคนของตัวเอง: ตารางอยู่ที่ verifier ของระบบนั้น (ทำแล้วในรีโป runtime 🔒)
* ระบบ coordination: ช่องบนใบงาน (ชื่อที่ประกาศ · บริบท · ความสามารถ · หมายเหตุตัวตน) ควรมีตารางเดียวกันหนึ่งที่
  — **เป็นข้อเสนอ ไม่ใช่คำสั่ง** maintainer ตัดสิน
* ที่นี่จะอ้างตารางนี้เป็นเกณฑ์ใน conformance criteria (ADR-0007)
