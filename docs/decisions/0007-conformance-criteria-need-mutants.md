# ADR-0007: ทุกทางที่เกณฑ์จะไม่ผ่านได้ ต้องมี mutant พิสูจน์ว่ามันยิงจริง

**Status:** Proposed
**Date:** 2026-10-12
**Depends on:** ADR-0003 · ADR-0004 · ADR-0006
**Blocking:** —
**Supersedes:** —
**Related ws-001:** `dec-f7cbd10c` เกณฑ์ 2ก/2ข · `dis-514ae7a7` seq 13 ข้อ ค-1 · seq 14 · `dis-fa078bf8` seq 88 · seq 96

## Context

รีโปนี้ถือ **conformance criteria** ตามขอบเขตที่ใบ boundary กำหนด · เกณฑ์ที่ประกาศแล้วไม่มีใครวัด
เป็นเอกสารที่วางอยู่ข้าง ๆ ไม่ใช่สัญญา

✅ แผลที่พิสูจน์แล้วสองรูป ทั้งคู่เป็นตระกูลเดียวกัน:

**รูปที่หนึ่ง — ชุดวัดที่หลวมทำให้ของที่หลวมได้ใบรับรอง**
ที่ `dis-514ae7a7` seq 13 เราชี้ว่าเกณฑ์ *"audit สะอาด"* ของ runtime พิสูจน์แคบกว่าชื่อ — กลไกจริงคือ
บัญชีดำของชื่อช่องชั้นบนสุด บวก grep หาสี่สตริงที่รู้ล่วงหน้า · มันพิสูจน์ว่า *ความลับสี่ตัวที่เรารู้จักไม่อยู่ในนั้น*
ไม่ใช่ *ไม่มี argument อยู่ในนั้น* · **อันตรายกว่าแผลในของที่ถูกวัด เพราะตัววัดที่หลวมออกใบรับรองให้**

**รูปที่สอง — `0` ของ "ไม่มีปัญหา" กับ `0` ของ "วิธีตรวจใช้ไม่ได้ พิมพ์เหมือนกัน**
`dis-fa078bf8` seq 88: ทีม index 🔒 สแกน credential ได้ศูนย์ทั้งตาราง แล้วรู้ตัวว่าผลเป็นศูนย์
**น่าสงสัยในตัวเอง** จึงรัน control test กับของที่รู้ว่ามี → ตรวจเจอ ⇒ วิธีนี้เห็นของจริงได้ ⇒ ศูนย์เป็นศูนย์จริง

✅ และทีม consumer 🔒 ไล่ชุดวัดของตัวเองด้วยหลักนี้ (`dis-fa078bf8` seq 96) แล้วพบว่า
**3 ใน 13 ทางที่เกณฑ์จะไม่ผ่านได้ ไม่เคยถูกเรียกเลย** ทั้งที่รายงาน `self-test 8/8` มาหลายรอบ
เขาสรุปความต่างไว้คมที่สุด:

> `self-test 8/8` ตอบว่า *mutant ที่มีถูกจับครบไหม* — **ไม่ได้ตอบว่าเกณฑ์ที่ประกาศไว้ถูกพิสูจน์ครบไหม**

## Options

### A. บังคับความครอบคลุมของทางที่ fail ได้ + ให้สคริปต์อ่านเกณฑ์จากซอร์สเอง (แนะนำ)

* ✅ ตอบคำถามที่ถูกข้อ — เกณฑ์ที่ประกาศถูกพิสูจน์ครบไหม
* ✅ สคริปต์ที่ `exit 1` เองกันได้ · กฎที่อยู่ในหัวคนกันไม่ได้ (พิสูจน์แล้วสองรอบในวงนี้)
* ❌ ต้องนับ "ทาง" ให้ได้ ซึ่งบังคับให้เขียนเกณฑ์ให้นับได้ด้วย

### B. นับจำนวน mutant ที่จับได้ อย่างที่ทำกันอยู่

* ✅ ง่าย และดูเหมือนเข้มอยู่แล้ว
* ❌ ตอบคำถามผิดข้อ · 3 ใน 13 ทางรอดมาได้ทั้งที่ 8/8 เขียว

## Decision

**A** — เกณฑ์ conformance ของ ecosystem นี้ต้องถือสี่ข้อ

1. **ทุกทางที่เกณฑ์จะ `fail` ได้ ต้องมี mutant ที่พิสูจน์ว่าทางนั้นยิงจริง**
   ความครอบคลุมนับเป็น *ทางที่ fail ได้* ไม่ใช่ *จำนวน mutant*
2. **สคริปต์ต้องอ่านรายการเกณฑ์จากซอร์สเอง แล้ว `exit 1` เมื่อมีทางที่ไม่ถูกคลุม**
   ไม่ใช่รายการที่คนต้องจำหรือ sync มือ
3. **คำศัพท์ผลต้องมีสี่ระดับ** ไม่ใช่ผ่าน/ไม่ผ่าน
   ```
   ผ่าน              วัดแล้วถูกต้อง
   ผ่านเท่าที่วัดได้    วัดได้บางส่วน · ห้ามอ่านเป็นผ่าน
   ไม่ผ่าน            วัดแล้วผิด
   วัดไม่ได้           ไม่มีของให้วัด
   ```
   สองระดับกลางคือสิ่งที่ทำให้ `0` และ `ผ่าน` โกหกไม่ได้ และเป็นรูปของเกณฑ์ 2ก/2ข ใน `dec-f7cbd10c`
4. **ชุดวัดต้องมี control test ถาวร** — ถ้ารันแล้วจับ mutant ไม่ได้ ชุดนั้นถือว่าสอบตกเอง
   > **ชุดทดสอบที่ไม่เคยพิสูจน์ว่าจับของผิดได้ คือชุดที่พิสูจน์ได้แค่ว่าของถูกผ่าน**

**Reason:** ข้อ 1–2 มาจากทีม consumer 🔒 ที่ค้นพบด้วยการไล่ของตัวเอง · ข้อ 3 เป็นรูปของเกณฑ์ที่อนุมัติแล้ว ·
ข้อ 4 พิสูจน์แล้วทั้งที่ชุดของ runtime (mutant สองตัว) และของ consumer (เจ็ดตัว)

**Authority:** — `Proposed` · ข้อ 3 มีฐานจาก `dec-f7cbd10c` ที่อนุมัติแล้ว ส่วนข้อ 1–2–4 ยังไม่มีใบ

## Consequences

* ชุด conformance ที่รีโปนี้จะรับโอนหรือเขียน ต้องผ่านสี่ข้อนี้กับตัวเอง **ก่อน**ใช้วัดคนอื่น
* เกณฑ์ที่เขียนกำกวมจนนับทางไม่ได้ ถือว่ายังไม่เสร็จ
* รายงานที่มีแต่ `ผ่าน`/`ไม่ผ่าน` ไม่รับเป็นหลักฐานของเกณฑ์ที่ยังวัดได้ไม่ครบ
