# ADR-0005: จองคีย์ `resource` ตั้งแต่ตอนนี้ — operation ที่มี target ต้องมีข้อนโยบายที่ระบุ resource

**Status:** Proposed
**Date:** 2026-10-12
**Depends on:** —
**Blocking:** approval contract (ยังไม่เขียน)
**Supersedes:** —
**Related ws-001:** `dis-58a707ef` seq 29 ข้อ 1 · seq 33 · `dis-514ae7a7` seq 7 · seq 13 ข้อ ข-1

## Context

✅ คำถาม *"สั่งเครื่องไหนได้"* ไม่มีที่เขียนในนโยบายของวงนี้มาตลอด · เราชี้ไว้ที่ `dis-58a707ef` seq 29 ว่า
tool ที่รันคำสั่งบนเครื่องอื่น **ไม่เข้ารูป host→tool→session** เพราะเครื่องที่รันคำสั่งไม่ใช่เครื่องที่รัน agent
และคำว่า host ถูกใช้แทนของสามอย่าง (ไซต์ · เครื่องที่รัน gateway · เครื่องปลายทางที่คำสั่งไปลง)

✅ `agent-platform` ไปตรวจแล้วตอบที่ seq 33 ว่า **แกนนั้นมีอยู่แล้วในสัญญา** คือ `policy/v1` `action.resource`
ตั้งแต่ v1.0.0 — **แต่เป็น string เปล่าที่ไม่มีกฎ ไม่มีรูปแบบ ไม่ required** จึงไม่มีใครเห็น และเขานับเป็นหนี้ของฝั่งเขา

✅ และเตือนไว้ด้วยว่า **อย่าเอา target ไปรวมกับ scope ของ capability** เพราะเป็นคำถามคนละข้อ

```
operation         ทำอะไร
resource/target   ลงมือกับอะไร
capability scope  อะไรทำให้ความสามารถนี้มีอยู่
```

สามแกนตั้งฉากกัน · ความเสี่ยงไม่ใช่การปิดทาง แต่คือ **การยุบรวมโดยไม่ตั้งใจ**

## Options

### A. จองคีย์ตอนนี้ พร้อมกติกาฝ่ายเดียวของข้อนโยบาย (แนะนำ)

* ✅ ตอนนี้ยังไม่มี write/privileged ที่ไหน จึงไม่มีของเก่าให้ migrate
* ✅ ข้อนโยบายที่เขียนก่อนหน้าจะไม่กลายเป็น "resource ใดก็ได้" โดยปริยาย
* ❌ มีคีย์ที่ยังไม่ถูกใช้อยู่ในสคีมาช่วงหนึ่ง

### B. เติมตอนเปิด write

* ✅ ไม่มีคีย์ที่ยังไม่ใช้
* ❌ ข้อนโยบายทุกข้อที่เขียนไว้ก่อนจะแปลว่า "resource ใดก็ได้" — **ผ่อนออก ไม่ใช่แคบลง**
  ซึ่งเป็นทิศทางที่ผิดและเป็นเหตุผลเดียวกับที่ทะเบียนล้าสมัยต้องทำให้ระบบแคบลง (ADR-0004)

## Decision

**A** — จองคีย์ `resource` ในกติกานโยบายตั้งแต่ตอนนี้ พร้อมข้อเดียว

> **ข้อนโยบายที่ไม่ระบุ `resource` ให้สิทธิ์กับ operation ที่มี target semantics ไม่ได้**

และเงื่อนไขของด่านนี้อยู่ที่ **ข้อนโยบายฝ่ายเดียว** · ค่าที่ผู้เรียกส่งมาไม่มีน้ำหนักในการทำให้ด่านผ่าน

```
operation มี target · ข้อไม่ระบุ resource       →  ปฏิเสธ (resource_required)
operation มี target · ข้อระบุ · ผู้เรียกส่งมาไม่ตรง →  ปฏิเสธ (resource_mismatch)
```

ค่าที่ผู้เรียกส่งมาเป็นข้อมูลของฝ่ายที่ไม่ไว้ใจ — **หลักเดียวกับชื่อที่ผู้เรียกประกาศ** (ADR-0001, ADR-0002)

**เรื่องรูปแบบของค่า** ยังไม่ตัดสินที่นี่ · `agent-platform` รับไปเขียนกฎ และขอตัวอย่างของจริงสองชนิด
ซึ่งเราส่งไปแล้ว: เครื่องปลายทางของ remote-shell (unique ต่อ instance) และ target ของ first-party tool
(กระทู้ · workspace) ที่สคีมาเราคุมเอง

**Authority:** — `Proposed`

## Consequences

* กติกานโยบายมีคีย์ที่ยังไม่มีใครใช้ จนกว่าจะมี operation ที่มี target ตัวแรก — **เป็นสภาพที่ต้องการ**
* `operation` ที่แปลว่า *สั่งให้อะไรทำงาน* ต้องถือว่ามี target semantics แม้ผลจะย้อนกลับได้
* ห้ามเอา `resource` ไปรวมกับ scope ของ capability ตามที่ `agent-platform` เตือน
